    About FPGAForge
    
            
    FPGAForge is a browser-based FPGA development and simulation environment. You write Verilog, assign pins with a Xilinx-style .xdc file, and run the design on a detailed, pin-accurate model of a real development board — with switches, buttons, LEDs, displays, serial port, VGA monitor, SD card, keyboard, audio and measurement instruments. Nothing needs to be installed and no hardware is required.
    
            
    Supported boards: Digilent Nexys A7-50T / A7-100T (Artix-7) and AMD Xilinx ZCU102 (Zynq UltraScale+). Pin numbers match the official master XDC files, so constraints move between FPGAForge and Vivado unchanged.
    

            
    Getting started
    
            
      
              
    1. Create an account with your email and a password (at least 6 characters). FPGAForge sends a verification email — click the link in it, then press I’ve verified my email. Use Resend email if it does not arrive (check spam), and Forgot password? on the sign-in screen for a reset link.
      2. 
              
    2. Choose your workspace folder — a folder on your PC where FPGAForge saves all your work. Choose the same folder every time you sign in.
      3. 
              
    3. The welcome screen opens: start a New project, continue a recent one, import a Vivado project, or open one of the 24 examples.
      4. 
              
    4. Press Validate, then Run on board. Click switches and buttons on the board while it runs.
      5. 
            
    
            
    Where your work is kept. After every sign-in FPGAForge asks for your workspace folder (Chrome or Edge on a computer). The first time, choose or create an empty folder; next time, one click on Reconnect opens the same folder and all your previous projects come back exactly as you left them. Every project is saved automatically in its own sub-folder, named after the project:
    
            
    Your folder/
├── fpgaforge_workspace.json      (marks the folder as yours)
└── <Project name>/
    ├── *.v, *.xdc, *.bd.json …     your source files
    ├── fpgaforge_project.json      board and settings
    ├── waveforms/                  last_run.vcd + the last 10 runs
    ├── logs/                       console.txt, serial.txt
    └── exports/                    PDF, MATLAB, Python, CSV, PNG …
    
            
    Renaming a project renames its folder; deleting a project deletes its folder. The 💾 button in the toolbar shows the connected folder. Nothing is uploaded to a server. In other browsers, choose Continue without a folder: projects are then kept in the browser and can be exported as .zip files.
    
            
    Unsaved changes. An orange dot next to the project name means there are edits not yet saved to your PC. Leaving the page or signing out then asks whether to save first — you can always choose to leave anyway.

    Creating a project
    
            
      
              
    1. Board — choose Nexys A7-50T, A7-100T or ZCU102.
      2. 
              
    2. Design — start from a template, paste your Verilog or upload files. Errors are shown as you type.
      3. 
              
    3. Pins — the Pin planner lists every port of your top module. Ports with familiar names (clk, led, sw, btn, tx, rx, seg, an …) are assigned automatically; change any assignment from the dropdowns. A constraints file is generated for you.
      4. 
              
    4. Testbench (optional) — generate a starter testbench with clock, reset and stimulus.
      5. 
              
    5. Save & run creates the project, validates it and starts the board.
      6. 
            
    
            
    You can reopen the Pin planner at any time from the button under the editor.
    

            
    Writing Verilog
    
            
    Supported: modules with parameters and localparam; assign; always @(posedge …), @(negedge …) and @(*); blocking and non-blocking assignments; if, case, casez; for, while, repeat, forever; generate for/if; functions and tasks (tasks may contain delays and call other tasks); signed arithmetic, $signed/$unsigned, >>>; memories with $readmemh; initial blocks.
    
            
    Testbench features: delays (#10), event controls, $display, $monitor, $time, $realtime, $finish, hierarchical references such as uut.counter, force / release, variables declared inside begin … end blocks, real variables with %f formatting, and string registers (for labels in messages).
    
            
    Xilinx primitives (for netlists): LUT1–LUT6, LUT6_2, FDRE/FDSE/FDCE/FDPE, CARRY4/CARRY8, MUXF7–MUXF9, SRL16E/SRLC32E, IBUF/OBUF/IBUFDS/OBUFDS/BUFG/BUFGCE.
    
            
    Limits: arithmetic is done on signals up to 32 bits wide (wider registers are allowed for text and equality checks); x values simulate as 0 and z as a pulled-up 1. VHDL, SystemVerilog classes and interfaces, and MicroBlaze or other processor IP are not supported.
    

            
    Constraints (XDC)
    
            
    The .xdc file decides what every port connects to. FPGAForge reads set_property PACKAGE_PIN, IOSTANDARD, create_clock and get_ports with buses ({led[0]}) — the same syntax as the master XDC files, so you can uncomment lines from them directly.
    
            
    Examples: a port on H17 drives LED LD0 on the Nexys A7; D4 is the Nexys UART output to the PC and C4 the input; on the ZCU102, AN14 reads DIP switch 0 and F13/E13 are the UART. The Pin map tab lists every pin of the selected board with its function and what your design connects to it. If only the _P side of a differential clock is constrained, the _N side is placed automatically, as in Vivado.
    

            
    Validate
    
            
    Validate checks the whole project before it can run on the board. Every message has a Vivado-style code, a link to the file and line, and a suggested fix.
    
            
      
              
    • Syntax and elaboration (HDL-SYN) — parse errors, unknown signals and modules, width problems.
      • 
              
    • Constraints (XDC-0, UCIO-1) — missing constraints file, ports without a pin, pins used twice, outputs placed on input-only pins.
      • 
              
    • Multiple drivers (MDRV-1) — the same signal assigned from more than one block.
      • 
              
    • Combinational loops — logic that feeds back on itself without a register.
      • 
              
    • Block design DRC — unconnected inputs, width mismatches, duplicate names.
      • 
            
    
            
    Any edit clears the green ✓ Validated state, so the design is always checked as it is now. A testbench-only project does not need validation: use Run testbench.
    

            
    Running on the board
    
            
      
              
    • Run on board picks the top module whose ports are in your XDC (or the one set under Board top), connects the board clock and peripherals, and runs continuously until you press Stop.
      • 
              
    • Run for runs exactly the time you enter (ns, µs, ms, s or clock cycles) and pauses; press it again to step further. Pause (F8) freezes the board, Restart starts again from reset.
      • 
              
    • Speed control (the ⏱ menu in the toolbar, like a video player): 0.25× to 5× or Max. Shortcuts: Shift + > faster, Shift + < slower.
      • 
              
    • 1× means real time. A browser cannot execute 100 million clock cycles per second, so FPGAForge scales design time: free-running clock dividers (cnt <= cnt + 1 where only high bits such as cnt[22] are used) advance 1024 counts per step, and large timer constants (cnt == 49_999_999) are divided by 1024. Button debouncers, one-second ticks, blinkers and clocks then behave exactly as on the real board, and the simulator paces itself to the speed you chose. The console lists every divider and constant that was scaled.
      • 
              
    • Max is cycle-exact: nothing is scaled and the simulator runs as fast as it can (typically 1–7 million cycles per second, i.e. 15–100× slower than a 100 MHz board). Use it for UART, VGA and DSP designs, or when you need exact cycle counts. Designs without dividers or long timers automatically run at full speed at every setting.
      • 
              
    • The status line shows the speed actually achieved, for example “1.0× real time”, or the simulator limit if a very large design cannot keep up.
      • 
            
    

            
    Board I/O
    
            
      
              
    • Switches — click to toggle. Buttons — press and hold with the mouse. CPU reset (Nexys) is active-low, like the real button.
      • 
              
    • LEDs and RGB LEDs — brightness follows the average duty cycle, so PWM dimming looks right.
      • 
              
    • 7-segment display — eight digits driven by AN[7:0] and segments CA…CG, DP (all active-low); multiplexed displays appear steady.
      • 
              
    • Pmod headers — any constrained Pmod pin can be watched in the Waveform or driven from the Signals tab.
      • 
              
    • Signals tab — shows every port and internal signal live; VIO outputs from a block design can be set by typing.
      • 
            
    

            
    UART (serial monitor)
    
            
      
              
    1. Constrain your transmitter to the board’s TX pin (Nexys D4, ZCU102 F13) and your receiver to RX (Nexys C4, ZCU102 E13).
      2. 
              
    2. Run on board, open Serial monitor and choose the same baud rate as your design (115200 in the examples).
      3. 
              
    3. Text from the FPGA appears in the window; type in the box and press Enter to send bytes to the FPGA. The TX/RX LEDs near the USB connector flicker with traffic. Example: UART hello + echo.
      4. 
            
    

            
    VGA monitor (Nexys A7)
    
            
    Drive VGA_R/G/B[3:0], VGA_HS and VGA_VS with standard 640×480 @ 60 Hz timing (25 MHz pixel clock — every fourth 100 MHz cycle — 800×525 total, active-low syncs). Run on board and open the VGA tab, or click the VGA connector. A full frame is 1.68 million clock cycles, so a new picture arrives every one to a few seconds. Example: VGA bouncing square.
    

            
    microSD card (Nexys A7)
    
            
    Double-click the microSD slot to insert a card, add files (up to 2 MB each) or type a text file. Files are stored back-to-back from sector 0 (raw, no file system); the table shows where each file starts. Your design talks to the card in SPI mode: SD_DAT3 chip select, SD_CMD MOSI, SD_DAT0 MISO, SD_SCK clock; drive SD_RESET low to power it, and SD_CD reads 0 when a card is inserted. Commands CMD0, CMD8, CMD55/ACMD41, CMD58, CMD17/18 (read), CMD24 (write) and CMD12 are supported, with SDHC block addressing. Written sectors are kept with the project. Example: microSD card reader.
    

            
    USB keyboard (Nexys A7)
    
            
    Double-click the USB HOST port and choose USB keyboard (selected automatically when a design uses PS2_CLK F4 / PS2_DATA B2). Run on board, click the board and type: keys are sent as PS/2 scan codes, set 2 (make code, F0 + code on release, E0 prefix for arrows), exactly as the board’s USB controller does. Examples: USB keyboard → 7-segment and USB keyboard decoder.
    

            
    Audio (Nexys A7)
    
            
    Microphone: in the Audio tab choose a test tone or an audio file. Your design generates M_CLK (1–3.3 MHz) and reads PDM bits on M_DATA. Speaker: drive AUD_PWM as open drain (assign AUD_PWM = bit ? 1'bz : 1'b0;) and set AUD_SD high; after running for a while, press Play captured audio to hear it at real pitch. Example: Microphone → speaker loopback.
    

            
    Power and programming modes
    
            
      
              
    • Power switch — click to turn the board off and on. Switching on boots from the selected mode with a programming animation.
      • 
              
    • Mode jumpers (Nexys JP1 + JP2) or boot switch (ZCU102 SW6) — click to cycle. JTAG: Run on board programs the FPGA from the PC. QSPI: double-click the flash chip to store the current design; it then starts on every power-up. SD / USB: the design stored on the card or stick boots at power-on.
      • 
            
    

            
    Testbenches
    
            
    A testbench is a module without ports. Run testbench simulates it until $finish, until no more events are scheduled, or until the limit set under Testbench stops after (10 µs to 10 s; the default is 100 ms). $display and $monitor output appears in the Console, and the waveform opens when the run ends. Designs that model real-time delays — debouncers, one-second ticks — need hundreds of milliseconds of simulated time, which can take a minute or more; choose the limit accordingly.
    

            
    Waveform viewer
    
            
      
              
    • Live waveform: while the board runs, top-level ports are recorded continuously (switch it off under the waveform toolbar to run faster). After a testbench, all signals are available.
      • 
              
    • Navigate: scroll to zoom, Shift+scroll or drag to pan, click to place a cursor; Fit shows the whole run. Add signal… adds internal nets.
      • 
              
    • Right-click a signal name for radix (binary, octal, hex, unsigned, signed, ASCII), style (digital, analog hold, analog linear), colour, row height and order.
      • 
              
    • Whole run: the waveform keeps everything from 0 s until Stop. A signal that changes millions of times (a fast clock) stops being stored after about 1.5 million changes; a regular clock is then drawn as continuing, labelled with its frequency, and other busy signals are marked “not stored after …”. Slower signals stay complete.
      • 
            
    

            
    Plot · MATLAB · Python
    
            
    After a board run or testbench — or after opening any .vcd file with Open VCD… (for example a Vivado pdc_dump.vcd) — press 📈 Plot · MATLAB · Python in the waveform toolbar, or choose MATLAB script, Python script or Plot here when saving after Stop.
    
            
      
              
    1. Signals — tick the signals you need (the filter helps with large Vivado dumps). Give each a figure number, mark multi-bit values as signed (two’s complement; All signed toggles every selected signal), and optionally a scale — a number or expression such as 180/(2^29*pi) to turn a CORDIC phase into degrees.
      2. 
              
    2. Time range — the whole waveform, the visible window, or a custom from–to range.
      3. 
              
    3. Figures — a title, a layout (Overlay: all signals on one axes with a legend; Subplots: one axes per signal, linked in time) and a Y-axis label for each figure.
      4. 
              
    4. Output — data inside the script (paste and run), or a CSV file plus a script that reads it (best for long runs).
      5. 
            
    
            
      
              
    • Plot here opens a MATLAB-style figure window: click a curve for a data tip with its X and Y values, drag to pan, scroll to zoom, Zoom for a zoom box, double-click or Restore to reset, right-click to clear data tips, Save PNG.
      • 
              
    • MATLAB — Copy and paste into MATLAB or MATLAB Online, or Save .m. Waveforms are drawn with stairs, with grid, legend, titles and linked subplots.
      • 
              
    • Python — Copy or Save .py, then run with python file.py (needs pip install matplotlib). The plot uses MATLAB’s colours and legend, and clicking a curve pins a data tip.
      • 
              
    • Save CSV writes the same data as a table: a Time column and one column per signal.
      • 
            
    
            
    When a workspace folder is connected, all of these files are saved into the project’s exports/ folder.
    

            
    Instruments
    
            
    Open Instruments while the board runs (or after a testbench) and pick one or two signals — any port or internal net, as unsigned or signed.
    
            
      
              
    • Oscilloscope — knobs for time/div, horizontal position, trigger level, and volts/div and position for each channel (drag, scroll or use arrow keys; double-click resets). Autoset, single shot, time and voltage cursors, math channel (CH1±CH2, CH1×CH2), XY mode and persistence.
      • 
              
    • Spectrum analyser — FFT in dBFS with reference level and dB/div, Hann or rectangular window, averaging, max hold and a table of the strongest peaks. Tick I/Q to analyse CH1 + j·CH2 as complex baseband.
      • 
              
    • Constellation and eye diagram — set samples per symbol and turn the offset knob until the points are tight and the eye is open.
      • 
              
    • Function generator — drives any input port with sine, square, triangle, sawtooth, noise or DC; frequency, amplitude and offset knobs.
      • 
            
    
            
    Examples: Nexys RF demo: DDS + QPSK and ZCU102 RF demo.
    

            
    Block design
    
            
    In the editor tab bar choose + → Block design. Click or drag IP blocks from the catalog onto the canvas, drag from an output pin to an input pin to connect them, right-click a pin → Make external to create a top-level port, and double-click a block to customize it. Validate design runs design-rule checks; View generated HDL shows the Verilog wrapper, which becomes the top module you constrain with the Pin planner.
    
            
    IP catalog: Constant, Concat, Slice, Utility Vector/Reduced Logic, Utility Buffer, Clocking Wizard, Processor System Reset, Binary Counter, Adder/Subtracter, Multiplier, Accumulator, Divider, RAM-based Shift Register, Block Memory, FIFO, DDS Compiler, CORDIC, FIR Compiler, ILA, VIO, plus FPGAForge blocks (clock enable, debouncer, PWM, UART TX/RX, 7-segment driver). ILA probes appear in the live waveform automatically; VIO outputs are set in the Signals tab.
    

            
    Vivado projects and netlists
    
            
    Zip a Vivado project folder and drop the .zip on the page (or use Import). FPGAForge reads the .xpr, takes the design, simulation and constraint files, selects the matching board and the top modules Vivado uses, and shows bitstream details if a .bit is included. Without an .xpr, every .v and .xdc in the zip is imported.
    
            
    A .bit file is a configuration image and cannot be simulated. To simulate exactly what Vivado implemented, run in the Vivado Tcl console:
    
            
    open_run impl_1
write_verilog -mode funcsim -force sim_netlist.v
    
            
    and import sim_netlist.v with your XDC. MMCM/PLL, block RAM and DSP primitives are not modelled yet.

    Troubleshooting
    
            
      
              
    • Run on board is greyed out — press Validate and fix the listed errors; any edit requires validating again.
      • 
              
    • Buttons respond late or a clock is slow — choose a numeric speed such as 1× (real time) instead of Max; the console then lists the scaled dividers. If nothing is listed, the design’s timing is not based on a counter divider or timer constant.
      • 
              
    • A port does nothing — check its PACKAGE_PIN in the Pin map tab; ports without a pin are reported by Validate.
      • 
              
    • Testbench stops early — raise Testbench stops after, or check that your testbench ends with $finish.
      • 
              
    • No workspace folder option — folder saving needs Chrome or Edge on a computer; other browsers keep projects in the browser and can export zips.
      • 
              
    • Verification email missing — check spam or promotions, then press Resend email (once a minute).
      • 
              
    • Plot shows huge numbers instead of negative values — mark the signal as Signed in the plot dialog.
      • 
              
    • Forgot your password — use Forgot password? on the sign-in screen.
